# 🐛 Система управления багами

Веб-приложение для управления багами проекта с системой заданий, баллов и ролевым доступом.

## ✨ Основные возможности

- 🔗 **Вход по magic link** - безопасная авторизация без паролей
- 👥 **Роли пользователей**: Администратор, Куратор, Программист, Тестер
- 🐛 **Управление багами** - создание, редактирование, отслеживание статусов
- 📋 **Система заданий** - создание, назначение и принятие заданий
- ⭐ **Система баллов** - автоматическое начисление и ручное управление
- 📊 **Статистика** - детальная аналитика по багам и заданиям
- 📝 **История изменений** - полная история статусов и работавших пользователей
- 🔍 **Поиск и фильтрация** - быстрый поиск по багам
- 🎨 **Современный UI** - удобный и интуитивный интерфейс
- 📱 **Адаптивный дизайн** - работает на всех устройствах

## 🛠 Технологии

- **Frontend**: React 18
- **Backend**: Node.js + Express
- **Авторизация**: JWT (JSON Web Tokens)
- **Хранение данных**: JSON файлы (легко заменить на БД)

## 📦 Установка

1. Клонируйте репозиторий
2. Установите зависимости:
```bash
npm run install-all
```

Или вручную:
```bash
npm install
cd client
npm install
```

3. Создайте файл `.env` в папке `client`:
```
DANGEROUSLY_DISABLE_HOST_CHECK=true
WDS_SOCKET_HOST=localhost
WDS_SOCKET_PORT=3000
```

## 🚀 Запуск

Запуск сервера и клиента одновременно:
```bash
npm run dev
```

Или отдельно:

**Backend** (порт 5000):
```bash
npm run server
```

**Frontend** (порт 3000):
```bash
npm run client
```

## 🐛 Статусы багов

- **Открыт** - новый баг, ожидает обработки
- **В работе** - баг взят в разработку
- **Решен** - баг исправлен, ожидает проверки
- **Не воспроизводится** - баг не удалось воспроизвести (автоматически закрывается)
- **Закрыт** - баг проверен и закрыт

### Ограничения по статусам

- При создании баг всегда получает статус "Открыт"
- Программист не может вернуть баг в статус "Открыт"
- Программист не может закрыть баг напрямую (использует "Не воспроизводится")
- Только админ может закрывать баги напрямую
- Закрытые баги может редактировать только админ

## 📋 Система заданий

### Типы заданий

1. **Обычные задания** - создаются куратором/админом для тестеров
2. **Задания проверки багов** - автоматически создаются при изменении статуса бага на "Решен"

### Возможности заданий

- ✅ **Назначение** - куратор/админ может назначить задание конкретному тестеру
- ✅ **Принятие** - любой пользователь может принять неназначенное задание
- ✅ **Выполнение** - пользователь, принявший задание, может изменить его статус
- ✅ **Автоматическое закрытие бага** - при выполнении задания проверки баг автоматически закрывается

### Статусы заданий

- **Ожидает** - задание создано, но не принято
- **В работе** - задание принято и выполняется
- **Выполнено** - задание завершено (начисляются баллы)
- **Отменено** - задание отменено

## ⭐ Система баллов

### Автоматическое начисление

- **Высокий приоритет бага**: +10 баллов
- **Средний приоритет бага**: +5 баллов
- **Низкий приоритет бага**: +2 балла
- **Выполнение задания**: баллы устанавливаются при создании задания

### Ручное управление

- Администратор может начислять и снимать баллы вручную
- Указывается причина изменения баллов
- Баллы не могут уйти в минус (минимум 0)

## 🔄 Автоматизация процессов

### При изменении статуса бага на "Решен"
1. Автоматически создается задание проверки
2. Задание доступно любому пользователю для принятия
3. После выполнения задания баг автоматически закрывается

### При установке статуса "Не воспроизводится"
1. Баг автоматически получает дату закрытия
2. Статус остается "Не воспроизводится" (не меняется на "Закрыт")
3. Баг считается закрытым для логики доступа

## 📊 Статистика

- **Всего багов** - общее количество
- **Открыто** - баги со статусом "Открыт"
- **В работе** - баги со статусом "В работе"
- **Решено** - баги со статусом "Решен"
- **Закрыто** - баги со статусом "Закрыт" или "Не воспроизводится"
- **Высокий приоритет** - только открытые баги с высоким приоритетом

## 📝 История и отслеживание

### История изменений статуса
- Полная история всех изменений статуса бага
- Показывает кто, когда и на какой статус изменил
- Отображается в обратном порядке (последние изменения сверху)

### Кто работал с багом
- Список всех пользователей, которые меняли статус бага
- Даты первого и последнего взаимодействия
- Отображается в деталях бага

## 🔗 Вход по magic link

### Создание ссылки для администратора

Для создания magic link для администратора используйте команду в терминале:

```bash
npm run create-admin-link
```

Или напрямую:

```bash
node server/createAdminLink.js
```

Скрипт автоматически найдет администратора, создаст ссылку и выведет её в консоль. Ссылка будет действительна 1 час и одноразовая.

### Создание ссылок для других пользователей

1. Войдите в систему как администратор или куратор
2. Перейдите в админ-панель
3. Нажмите кнопку "⭐" рядом с пользователем для создания magic link
4. Ссылка копируется в буфер обмена
5. Ссылку отправляют пользователю
6. Пользователь переходит по ссылке и автоматически входит

### Формат ссылки
```
http://localhost:3000/login/<token>
```

**Важно:**
- Ссылка действительна 1 час
- Ссылка одноразовая (после использования становится недействительной)
- Для создания ссылок через админ-панель требуется авторизация

## 🔌 API Endpoints

### Авторизация
- `POST /api/auth/create-link` - создать magic link (админ/куратор)
- `POST /api/auth/login-link` - вход по magic link
- `GET /api/auth/me` - получить текущего пользователя

### Пользователи
- `GET /api/users` - получить пользователей (с фильтрацией по ролям)
- `POST /api/users` - создать пользователя (админ/куратор)
- `PUT /api/users/:id` - обновить пользователя (админ)
- `DELETE /api/users/:id` - удалить пользователя (админ)
- `POST /api/users/:id/points` - изменить баллы (админ)

### Баги
- `GET /api/bugs` - получить баги (с фильтрацией по ролям)
- `GET /api/bugs/:id` - получить баг по ID
- `POST /api/bugs` - создать баг
- `PUT /api/bugs/:id` - обновить баг (программист/куратор/админ)
- `DELETE /api/bugs/:id` - удалить баг (программист/куратор/админ)
- `GET /api/stats` - получить статистику

### Задания
- `GET /api/tasks` - получить задания (с фильтрацией по ролям)
- `POST /api/tasks` - создать задание (куратор/админ)
- `POST /api/tasks/:id/accept` - принять задание
- `PUT /api/tasks/:id` - обновить задание
- `DELETE /api/tasks/:id` - удалить задание (куратор/админ)

### Профиль
- `GET /api/profile` - получить личный кабинет с статистикой

**Примечание**: Все запросы (кроме логина) требуют токен в заголовке `Authorization: Bearer <token>`
