# 🐛 Система управления багами

Веб-приложение для тестеров проекта с функционалом управления багами.

## Возможности

- 🔗 **Вход по ссылке** - безопасная авторизация через magic links
- 👥 **Роли пользователей**: Администратор, Куратор, Тестер
- 📋 **Система заданий** - кураторы могут создавать и назначать задания тестерам
- ⭐ **Система баллов** - автоматическое начисление баллов за найденные баги и выполненные задания
- 👤 **Личные кабинеты** - статистика, баллы и история для каждого тестера
- ✅ Создание, просмотр, редактирование и удаление багов
- 📊 Статистика по багам (общее количество, по статусам, по приоритетам)
- 🔍 Поиск и фильтрация багов
- 🎨 Современный и удобный интерфейс
- 📱 Адаптивный дизайн

## Технологии

- **Frontend**: React 18
- **Backend**: Node.js + Express
- **Авторизация**: JWT (JSON Web Tokens)
- **Хранение данных**: JSON файлы (можно легко заменить на базу данных)

## Запуск

**Важно:** Перед первым запуском клиента создайте файл `.env` в папке `client` со следующим содержимым:
```
DANGEROUSLY_DISABLE_HOST_CHECK=true
WDS_SOCKET_HOST=localhost
WDS_SOCKET_PORT=3000
```

Это необходимо для корректной работы webpack-dev-server в Windows.

Запуск сервера и клиента одновременно:
```bash
npm run dev
```

Или отдельно:

**Backend сервер** (порт 5000):
```bash
npm run server
```

**Frontend клиент** (порт 3000):
```bash
npm run client
```

## Использование

### Первый вход

При первом запуске создается дефолтный администратор. Для входа нужно получить magic link от администратора.

### Система ролей

**Администратор:**
- Создание пользователей (тестеров и кураторов)
- Создание magic links для входа
- Просмотр всех багов и заданий
- Полный доступ к системе

**Куратор:**
- Создание заданий для своих тестеров
- Создание magic links для своих тестеров
- Просмотр багов и заданий своих тестеров
- Управление тестерами, назначенными ему

**Тестер:**
- Создание багов (с автоматическим начислением баллов)
- Выполнение назначенных заданий
- Просмотр своего профиля и статистики
- Просмотр своих багов и заданий

### Как работает вход по ссылке

1. Администратор или куратор создает пользователя
2. Нажимает кнопку "🔗" рядом с пользователем для создания magic link
3. Ссылка копируется в буфер обмена
4. Ссылку отправляют тестеру (через email, мессенджер и т.д.)
5. Тестер переходит по ссылке и автоматически входит в систему
6. Ссылка действительна 24 часа и может быть использована только один раз

### Система баллов

- **Высокий приоритет бага**: +10 баллов
- **Средний приоритет бага**: +5 баллов
- **Низкий приоритет бага**: +2 балла
- **Выполнение задания**: баллы устанавливаются куратором при создании задания

## Структура бага

- **Название** - краткое описание проблемы
- **Описание** - подробное описание
- **Статус** - открыт, в работе, решен, закрыт
- **Приоритет** - низкий, средний, высокий
- **Тестер** - имя тестировщика
- **Шаги воспроизведения** - пошаговая инструкция
- **Ожидаемый результат** - что должно произойти
- **Фактический результат** - что происходит на самом деле
- **Окружение** - информация о системе/браузере

## API Endpoints

### Авторизация
- `POST /api/auth/create-link` - создать magic link для пользователя (админ/куратор)
- `POST /api/auth/login-link` - вход по magic link
- `GET /api/auth/me` - получить текущего пользователя (требует токен)

### Пользователи (админ/куратор)
- `GET /api/users` - получить всех пользователей (куратор видит только своих тестеров)
- `POST /api/users` - создать нового пользователя
- `PUT /api/users/:id` - обновить пользователя
- `DELETE /api/users/:id` - удалить пользователя

### Задания (админ/куратор/тестер)
- `GET /api/tasks` - получить задания (тестер видит только свои, куратор - созданные им)
- `POST /api/tasks` - создать задание (админ/куратор)
- `PUT /api/tasks/:id` - обновить задание
- `DELETE /api/tasks/:id` - удалить задание (админ/куратор)

### Профиль
- `GET /api/profile` - получить личный кабинет с полной статистикой

### Баги (требует авторизации)
- `GET /api/bugs` - получить все баги
- `GET /api/bugs/:id` - получить баг по ID
- `POST /api/bugs` - создать новый баг
- `PUT /api/bugs/:id` - обновить баг
- `DELETE /api/bugs/:id` - удалить баг
- `GET /api/stats` - получить статистику

**Примечание**: Все запросы к API (кроме логина) требуют токен авторизации в заголовке `Authorization: Bearer <token>`

## Данные

Данные хранятся в JSON файлах в папке `server/data/`:
- `bugs.json` - баги
- `users.json` - пользователи (с баллами и статистикой)
- `tasks.json` - задания
- `magicLinks.json` - временные ссылки для входа

Файлы создаются автоматически при первом запуске. При первом запуске также создается дефолтный администратор.

## Структура данных

### Пользователь
- `id`, `username`, `name`, `email`
- `role`: `admin`, `curator`, `tester`
- `curatorId`: ID куратора (для тестеров)
- `points`: накопленные баллы
- `bugsFound`: количество найденных багов
- `tasksCompleted`: количество выполненных заданий

### Задание
- `id`, `title`, `description`
- `createdBy`: ID создателя (куратора/админа)
- `assignedTo`: ID тестера
- `status`: `pending`, `in-progress`, `completed`, `cancelled`
- `priority`: `high`, `medium`, `low`
- `points`: баллы за выполнение
- `area`: область тестирования
- `deadline`: срок выполнения
